# Этаж на тайлах и реальных спрайтах

Второй слой поверх генератора: планировка из [`docs/room_generation.md`](room_generation.md)
превращается в сетку тайлов и рисуется настоящими спрайтами проекта из
`spites/`.

```bash
python3 -m roomgen pixels --seed 12 --floor 1   # PNG: этаж целиком и крупный план
python3 -m roomgen export --seed 12             # JSON с сеткой тайлов для Godot
```

![Этаж на спрайтах](images/pixels_floor.png)

---

## 1. Три слоя, которые не знают друг о друге

| Слой | Файл | Что делает | Зависимости |
|---|---|---|---|
| Планировка | `generator.py` | какие комнаты, какого размера и где | stdlib |
| Тайлы | `tilemap.py` | комнаты и перемычки → сетка тайлов | stdlib |
| Картинка | `render_sprites.py` | тайлы → пиксели, мебель, враги | Pillow |

Разделение не косметическое: в Godot первые два слоя переносятся как есть
(чистый GDScript без нод), а третий заменяется на `TileMapLayer` и сцены комнат.
Генератор при этом не меняется вообще.

## 2. Масштаб

Масштаб мира выводится прямо из спрайтов. Дверь из `walls/floor_walls.png` —
35×60 px, реальная дверь 0.9×2.05 м, значит **1 тайл (16 px) ≈ 0.41 м**.
Дальше всё сходится: герой 20×36 px → 0.5×1.2 м, холодильник 28×56 px →
0.7×1.9 м, парта 48×39 px → 1.2×1.3 м.

| | Тайлов внутри | В метрах |
|---|---|---|
| Обычная комната | 70–94 × 50–66 | 29–39 × 21–27 м |
| Боссфайт | 126–150 × 102–122 | 52–62 × 42–50 м |
| Перемычка | 8 в ширину | 3.3 м |
| Этаж целиком | ~800 × 600 | ~330 × 250 м |

Полный список размеров — в [docs/room_generation.md](room_generation.md).
Тест `test_rooms_are_big_enough_for_gameplay` держит нижнюю границу.

### Карта в масштабе 1:1 больше не помещается в картинку

Этаж 800×600 тайлов по 16 px — это **около 110 мегапикселей**. Поэтому рендер
умеет рисовать сразу мелким тайлом: `tile_px=4` даёт обзор всего этажа в
четырёхкратном уменьшении (около 7 Мп), а `tile_px=16` оставлен для крупных
планов. Крупный план не строит карту целиком, а рисует только нужный кусок —
иначе ради одной комнаты в памяти оказывалось бы 430 МБ.

## 3. Планировка на тайлах

Генератор отдаёт комнаты уже прямоугольниками в тайлах (см.
[docs/room_generation.md](room_generation.md)), поэтому этому слою остаётся
немного:

* обвести каждую комнату кольцом стен, внутри положить пол;
* положить пол перемычек;
* прорезать проёмы в стенах с обеих сторон каждой перемычки;
* обвести стенами всё, что стало проходимым.

```
 ┌──────────┐        ┌────────┐
 │  КЛАСС   ├══┐  ┌══┤ СУНДУК │     ═ — перемычка (4 тайла в ширину)
 │          │  └──┘  │        │     ┤ — проём в стене комнаты
 └──────────┘        └────────┘
```

Два тайла перед проёмом изнутри комнаты помечаются занятыми (`APPROACH = 2`):
иначе шкаф встаёт ровно в дверях.

Этаж целиком — примерно 800×600 тайлов, то есть около 330×250 м. Размер
плавает от сида: планировка свободная.

Обход в ширину по проходимым тайлам подтверждает, что тайловая карта совпадает
с графом комнат: всё достижимо от спавна (`test_all_rooms_reachable_over_tiles`),
непроходимых огрызков нет (`test_no_orphan_corridors`), а на лестницу нельзя
попасть, если вырезать комнату босса (`test_stairs_only_behind_boss_on_tiles`).

## 4. Прогрессия

Перемычки соединяют комнату с комнатой: обойти комнату коридором нельзя, и
обязательный маршрут до босса — это просто кратчайший путь по графу. Генератор
задаёт его длину напрямую, поэтому ГДД 3.1 («основной путь 5–6 комнат»)
выполняется буквально, на каждом сиде.

Петли добавляют альтернативные маршруты (в среднем 1.1 на этаж), но по
построению не укорачивают путь до босса — обязательные комнаты остаются
обязательными.

## 5. Оформление и наполнение комнаты

`floors/tiles.png` — ровная сетка: тайл 16×16, шаг 32, начало (16,16).
Ряд 0 — кирпичные стены пяти цветов, дальше семейства полов по три ряда.
Тип комнаты выбирает семейство пола и цвет кирпича:

| Комната | Пол | Стены |
|---|---|---|
| Спавн | зелёный | коричневый кирпич |
| Обычная | школьная плитка | коричневый кирпич |
| Усложнённая | школьная плитка | **красный** кирпич |
| Столовая | паркет | светлый кирпич |
| Толчок | белая плитка | белый кирпич |
| Сундук, ивент | синий | оранжевый кирпич |
| Лестница | школьная плитка | белый кирпич |
| Босс | красный | **красный** кирпич |

Внутри семейства вариант тайла выбирается по координате и сиду — пол не выглядит
залитым одним цветом, но остаётся детерминированным. Коридоры и проёмы всегда
школьной плиткой: проход читается как проход, куда бы он ни вёл.

Предметы раскладываются четырьмя режимами, и два из них масштабируются:

| Режим | Что это | Число |
|---|---|---|
| `rows` | ровными рядами по всей комнате: парты, столы | **линейно от площади** |
| `wall_row` | вдоль верхней стены: шкафчики, кабинки, стойки | **корень от площади** |
| `wall` | вдоль верхней стены, ровно столько: доска, плита | фиксировано |
| `free` | врассыпную: сундук, монеты, три стойки с перками | фиксировано |

Разделение появилось из-за увеличения комнат. Мебель заполняет площадь, поэтому
парт в аудитории на 800 м² должно быть около полутора сотен — их число растёт
линейно от квадратных метров. А доска в классе одна, сколько бы он ни был, и
стоек с перками ровно три (ГДД 5.3) — эти не масштабируются вовсе.

Число врагов растёт **корнем** от площади, а не линейно: бой в обычной комнате
по ГДД длится 5–15 секунд, и линейный рост сделал бы это время недостижимым.

Раскладчик считает площадь спрайта в тайлах: спрайт «стоит» на тайле,
центрируется по горизонтали и растёт вверх, поэтому высокий шкаф сам отходит от
стены, а занятые тайлы больше никому не достаются. У персонажей вокруг остаётся
зазор в тайл, иначе два силуэта сливаются в один.

![Кабинет крупным планом](images/pixels_room_class.png)

| Комната | Что стоит |
|---|---|
| Спавн | герой + шкафчики |
| Обычная | доска + 9 парт + враги |
| Усложнённая | доска + парты + элитный враг + враги |
| Столовая | холодильник, плита, стойки, столы, монеты |
| Толчок | три унитаза, раковина |
| Сундук | сундук (второй — золотой), монеты |
| Ивент | доска, стеллажи, парты |
| Лестница | дверь + три звезды (три стойки с перками, ГДД 5.3) |
| Босс | босс + свита |

![Столовая](images/pixels_room_cafeteria.png)

Разница размеров читается лучше всего на боссфайте — актовый зал 13×11 м
против класса 8×6 м:

![Комната босса, этаж 3](images/pixels_room_boss.png)

Число врагов растёт с номером этажа (`--floor N`), как требует ГДД 4.4:
обычная комната `4 + этаж`, усложнённая `6 + этаж` плюс элита, и всё это
умножается на корень из отношения площади к опорной комнате.

## 6. Откуда взяты координаты спрайтов

Из `spites/` разобраны шесть листов. Координаты вырезок получены не на глаз:
по каналу прозрачности искались связные области вокруг заданной точки, поэтому
рамка совпадает со спрайтом пиксель в пиксель. `Atlas.get()` дополнительно
обрезает прозрачные поля.

| Лист | Что берётся |
|---|---|
| `floors/tiles.png` | пол и стены (ровная сетка 16×16) |
| `objects/furniture (2).png` | унитаз, раковина, холодильник, плита, стойка, доска, парта, стеллаж, шкафчик |
| `ui/coins-chests-etc-2-0.png` | сундуки, монеты, звёзды, сердца |
| `heros/main_hero/nameless.png` | герой |
| `heros/enemies/enemies.png` | «Переписанные», элита, босс |
| `walls/floor_walls.png` | дверь |

Все названные вырезки проверяются тестом `test_all_named_sprites_load`: если
художник подвинет спрайт на листе, тест это поймает.

**Чего в наборе не хватает:** отдельного спрайта лестничного пролёта. Сейчас
лестничная площадка обозначается дверью из `walls/floor_walls.png` — заменить
на настоящий спрайт достаточно одной строкой в `sprites.py`.

## 7. Экспорт в Godot

```bash
python3 -m roomgen export --seed 12 --out out/floor_12.json
```

В JSON лежит всё, что нужно сцене: комнаты с типами и их прямоугольниками в
тайлах, перемычки, обязательный маршрут, готовая сетка тайлов построчно и
таблица `tileset` — какие вырезки из `res://spites/floors/tiles.png` класть
под каждый тип комнаты.

```json
{
  "size_tiles": [834, 611], "spawn": 0, "boss": 4, "stairs": 5,
  "rooms": [{ "id": 4, "type": "boss", "rect_tiles": [392, 240, 144, 116],
              "doors_to": [3, 5] }],
  "corridors": [{ "between": [4, 5], "axis": "v",
                  "rect_tiles": [452, 356, 8, 24] }],
  "tiles": { "size": 16, "width": 834, "height": 611,
             "rows": ["2111111111113111411111...", "..."],
             "legend": {"0": "empty", "1": "floor", "2": "wall",
                        "3": "doorway", "4": "hall"} },
  "tileset": { "source": "res://spites/floors/tiles.png",
               "floor_by_room": {"cafeteria": "parquet", "boss": "red"} }
}
```

Папка `spites/` в репозитории лежит с теми же `.import`-файлами, что и в
Godot-проекте, и рассчитана на путь `res://spites/` — UID текстур не ломаются.
